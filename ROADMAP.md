# Roadmap

MDL v0.1 is the first public release. It is complete when every box below is
checked. Phases are ordered by dependency: each builds on the previous one.

## Phase 0: foundation

- [x] Repository, dual MIT / Apache-2.0 license, workspace (`mdl` library,
      `morphc` CLI)
- [x] MDL v1 moved from morpheus-c2: TOML frontend, IR, validation, plans,
      bit extraction, interpreter
- [x] Canonical JSON (RFC 8785) for artifact hashing, a strict parser (no
      duplicate keys), the normative rules in
      [spec/canonical-json.md](spec/canonical-json.md), and the first
      conformance vectors (`conformance/canonical/`, generated by V8)

## Phase 1: IR v2 core

- [x] IR v2 types (`crates/mdl/src/v2/ir.rs`): strict reading, normal
      form, `major.minor` versions, API stable under additions
- [x] Strict reader (`v2::read`): canonical checks, version check before
      the shape, typed reading from the canonical form, errors with JSON
      paths, digests
- [x] Artifacts: catalog, family, set; content-addressed by the SHA-256 of
      their canonical JSON; a set records the hashes it was validated
      against; each artifact records the lowest IR version its features
      need (so moving the compiler to 2.1 doesn't change unchanged
      artifacts' identities)
- [x] Families: encoding, byte order, alias and version locators, declared
      metadata
- [x] Layout: absolute and sequential entries, arrays (fixed, counted,
      remaining), reusable struct types, conditional entries, padding,
      variable-length strings and bytes
- [x] Validation for all of the above, with stable diagnostic codes and JSON
      Pointer paths; integers within ±(2^53 − 1); one spelling per instant;
      packet identification where the most specific packet wins
- [x] Catalog compatibility check between versions (additions and
      deprecations only)
- [x] Bindings file format, `Resolver` trait, file-backed resolver, set
      selection (version locator, else binding effective at ground time);
      the sets loaded for one family are checked together (unique versions),
      since stored artifacts can come from more than one build
- [x] Decoder: compiled in-memory program, identification index, record
      tree output, canonical values (composites, array samples), quality
- [ ] TOML frontend v2; examples updated, including mixed versions on one link
- [ ] `morphc build` (writes artifacts), `inspect`, `decode` (hex or file in,
      JSON out), `--set`
- [ ] Fuzzing (`cargo-fuzz`) for every decoder entry point
- [ ] Remove v1 (`ir`, `validate`, `interpret`, `plan`, `frontend`) and move
      `v2::*` up one level; decouple `bits` from v1 first

## Phase 2: commands (encode)

- [ ] Canonical commands and arguments in the catalog (types, units, ranges,
      states)
- [ ] Command layouts in sets: argument bindings, constants, computed
      lengths, payload checksums (CRC-16/32 variants, sum, xor)
- [ ] Inverse conversions (linear, states, monotonic tables; explicit inverse
      for polynomials)
- [ ] Encoder; `encode → decode` round-trip property tests; `morphc encode`

## Phase 3: encodings, units, calibrations

- [ ] CBOR and MessagePack payloads (JSON Pointer locations)
- [ ] Calibrations: lookup tables (linear or step, with extrapolation
      policy), natural cubic splines
- [ ] Units: UCUM subset with dimensional analysis; a field in a different
      but compatible unit is converted automatically (mV → V, degC → K)
- [ ] Time: Unix (s/ms/µs/ns), GPS week + seconds, boot-relative with
      correlation description

## Phase 4: interoperability

- [ ] JSON Schema for every IR artifact, generated and checked in
- [ ] Conformance suite: language-neutral cases (artifacts + payload hex +
      expected output or expected diagnostics) and a runner
- [ ] XTCE import frontend (SpaceSystem, parameter types with encodings and
      calibrators, sequence containers with base containers and restriction
      criteria)

## Phase 5: language bindings

All bindings share one coarse API: load artifacts, decode, encode, with
results as JSON or CBOR, so each binding stays thin.

- [ ] C ABI (`mdl-ffi`) with a generated header
- [ ] C++ (header-only wrapper over the C ABI)
- [ ] Go
- [ ] Python (PyO3)
- [ ] WebAssembly (browser and Node)
- [ ] Elixir (Rustler NIF)

## Phase 6: release

- [ ] The MDL specification (IR, semantics, canonical form, conformance)
- [ ] User guide (mdBook)
- [ ] CI: fmt, clippy, tests, MSRV, fuzz smoke, `cargo-deny`, conformance
- [ ] Benchmarks (decode throughput per encoding)
- [ ] Final crate names; publish to crates.io, PyPI, npm, Hex
- [ ] CHANGELOG, CONTRIBUTING, SECURITY, versioning policy
